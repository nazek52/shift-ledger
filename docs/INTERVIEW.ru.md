# Как объяснить Shift Ledger

Демонстрация: Alex создаёт инцидент и предлагает передачу Sam. Пока Sam не подтвердил, ответственность остаётся у Alex. Затем покажи обновление из двух вкладок: устаревшая версия получает 409, текст заметки не теряется.

Вопросы:

1. Почему обычного поля assigned_to недостаточно для передачи дежурства?
2. Что защищает version, а что — BEGIN IMMEDIATE? Что было бы при чтении версии вне транзакции?
3. Почему запись audit должна быть атомарной с изменением статуса?
4. Кто определяет actor: браузер или сервер? Попробуй изменить чужой инцидент разными ролями.
5. Почему append-only API не равен tamper-proof журналу? Какие полномочия остаются у администратора БД?

Практика: добавь идемпотентный ключ для создания инцидентов и проверь повтор после сетевого таймаута. Затем спроектируй SSO без хранения внешних токенов в логах. Для DevOps этот проект связывает инструменты с процессом работы дежурных и восстановлением контекста.

Это личный AI-assisted проект, а не заявление об опыте работы в реальном on-call. Разбери переходы и ошибки до собеседования.
